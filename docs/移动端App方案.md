# 移动端 App 方案建议（待主人拍板）

## 背景

- 归藏已有 WebDAV 协议 + 手机网页端响应式适配（`d5a5841`），日常在手机上浏览/下载已可用。
- 「移动端 App」定位为二期扩展，需要主人确认技术栈与需求范围后才可开工。

## 现状与 Gap 分析

| 场景 | 现状 | App 增量价值 |
|---|---|---|
| 浏览文件/相册/监控录像 | 手机浏览器可用（响应式） | 原生体验、推送通知 |
| 相册自动备份 | WebDAV + 第三方 App（PhotoSync/FolderSync）已可覆盖 | 内置一键备份、自动上传 |
| 文件上传下载 | 网页可用 | 断点续传更稳、离线缓存 |
| 系统监控告警 | 站内通知（需打开网页） | 系统推送（APNs/FCM） |

> 结论：**在未确认前不建议投入 App 开发**。先用网页端 + WebDAV 方案覆盖 90% 需求，成本为零。

## 技术栈对比（若要做）

| 维度 | uni-app | Flutter | 原生双端 |
|---|---|---|---|
| 语言 | Vue（与现有前端同栈） | Dart | Swift / Kotlin |
| 复用现有代码 | 可复用 api/ts 封装与组件逻辑 | 不可复用，需重写 | 不可复用 |
| 跨端 | iOS + Android + 小程序 | iOS + Android | 各自维护 |
| 推送 | 各家云厂商服务 | 需接第三方 | 原生 |
| 学习/维护成本 | 低（Vue 团队即战力） | 中 | 高 |

**建议：若主人确定要做，选 uni-app + Vue3**（与归藏前端同栈，api 层可直接迁移）。

## 建议的需求范围（MVP）

1. 登录 + 文件浏览/上传下载（断点续传）
2. 相册一键备份（后台任务 + 增量）
3. 监控录像查看（摄像头列表 + 日期 + 播放）
4. 磁盘/任务告警推送

## 建议的路径

**先不写 App**，把下面两件事做掉即可覆盖手机需求：
1. 网页端加入手机浏览器「添加到主屏幕」提示（PWA 化，已有响应式适配，成本低）
2. 按《手机相册备份接入指南》配置 WebDAV 客户端

等主人试用网页端 + WebDAV 后，若仍有痛点（如推送需求明确），再启动 App 开发。
